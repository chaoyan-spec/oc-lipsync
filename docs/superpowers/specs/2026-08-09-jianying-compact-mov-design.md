# 剪映兼容紧凑 MOV 导出设计

## 目标

将当前无法导入剪映的透明 WebM，替换为已经在用户剪映环境中验证可导入的透明 Animation MOV。导出只包含人物区域，不再替用户生成 1080×1920 成片画布。

## 已验证规格

- 容器：QuickTime MOV
- 视频编码：QuickTime Animation（`qtrle`）
- 像素格式：`argb`，保留 Alpha 透明通道
- 输出尺寸：320×366
- 帧率：15 fps
- 音频编码：AAC，96 kbps
- 13.43 秒实测大小：约 3.7 MB
- 实测结果：可导入剪映，清晰度满足用户需求

## 画面生成

闭嘴和张嘴素材均为 1000×1000 RGBA PNG，人物共同的不透明包围盒为：

```text
x = 213
y = 188
width = 622
height = 711
```

导出时先裁切该人物区域，再缩放至 320×366。嘴型仍由同一份音频时间轴在闭嘴、张嘴素材之间切换。输出不包含额外透明边距、竖屏画布、位置或成片尺寸信息。

## 用户界面

- 导出按钮文案改为“导出剪映透明 MOV”。
- 完成链接改为“导出完成，点击保存 MOV”。
- 下载文件名为 `<原音频名>-OC口播.mov`。
- 移除“OC 大小”控制，因为人物位置和缩放改由剪映负责。
- 预览播放与口型灵敏度、最短开嘴时间保持现状。

## 请求与响应

浏览器仍通过现有本机 `/api/export` 发送音频和嘴型时间轴，但不再发送角色缩放比例。服务器响应：

```text
Content-Type: video/quicktime
Content-Disposition: attachment; filename*=UTF-8''<encoded MOV filename>
```

浏览器保留现有可见保存链接，不依赖自动下载。

## 兼容与错误处理

- 输入继续支持 MP3、WAV、M4A。
- FFmpeg 不支持 `qtrle`、`argb` 或 AAC 时，沿用现有“导出失败，请重试”路径。
- 临时音频和导出文件继续在请求结束后清理。
- 文件大小限制、元数据限制、回环地址限制和路径安全规则保持不变。

## 验证

- 服务端真实导出测试断言 MOV 容器、`qtrle`、320×366、15fps、`argb` 和 AAC。
- 解码左上角像素并断言 RGBA 为 `0 0 0 0`。
- 浏览器请求测试断言不再发送 `scale`，保存文件名以 `.mov` 结尾。
- UI 测试断言删除 OC 大小控制，并显示 MOV 导出文案。
- 使用 `田林东路.m4a` 完整导出，目标大小约 3.7 MB，并由用户在剪映中再次验证。
- 重新生成 runtime-only ZIP，fresh unzip 后构建、启动和导出必须通过。

## 非目标

- 不生成最终 9:16 视频画布。
- 不保留 WebM 作为第二个导出按钮。
- 不在本轮修改口型算法、预览刷新或人物动作。
- 不接入剪映项目文件或自动操作剪映。

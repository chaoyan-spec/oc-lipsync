# OC 自适应透明 MOV 设计

## 目标

让导出画布自动贴合 OC 人物本体，不再把输出尺寸固定为 320×366。用户替换同尺寸的张嘴、闭嘴 PNG 后，不需要测量或填写裁切坐标；输出继续兼容已经验证可导入剪映的透明 Animation MOV。

## 用户体验

- 用户仍然只需导入口播音频并点击“导出剪映透明 MOV”。
- 页面不增加尺寸设置。
- 预览标签从固定尺寸改为“自动适应 OC · 剪映透明 MOV”。
- 导出的宽高跟随 OC 的透明边缘和原始比例。
- 人物四周保留 8px 的最终输出透明边距，避免头发、耳饰和描边贴边。

## 自动边界计算

服务端在每次导出前分别读取张嘴、闭嘴 PNG 的 Alpha 通道，并使用 FFmpeg `alphaextract,bbox=min_val=1` 获取所有 Alpha 大于 0 的像素边界。

两张图必须具有相同的源画布尺寸。服务端取两份边界的并集，保证嘴型切换时人物位置和输出画布不会跳动。当前两张 1000×1000 素材都会得到 `x=213, y=188, width=622, height=711`，但这些数值不再写死在编码器中。

如果任一素材无法读取、任一素材没有可见像素，或两张图画布尺寸不同，导出失败并返回现有的通用导出错误；不生成可能裁坏人物的文件。

## 输出尺寸

1. 以共同人物边界作为裁切区域。
2. 保持宽高比，将人物内容最长边缩小到最多 304px；小于 304px 的素材不放大。
3. 需要缩小时，两边按比例计算并取最接近的正偶数；小尺寸素材不缩放时，两边向下取正偶数。这样既避免视频编码的奇数尺寸兼容问题，也不会放大小素材。
4. 四周各增加 8px 透明边距，因此最终最长边不超过 320px。

当前 OC 的 622×711 人物区域将缩放为 266×304，四周各加 8px 边距后输出为 282×320。输出大小由计算结果决定，不再固定为 320×366。

## 编码流程

现有音频分析、嘴型时间轴和张嘴/闭嘴图片清单保持不变。FFmpeg 视频滤镜调整为：

1. 按共同边界裁切；
2. 使用 Lanczos 等比例缩放至计算出的内容尺寸；
3. 使用透明颜色补齐四周 8px；
4. 转换为 15fps、`argb`；
5. 使用 `qtrle` 写入 MOV，并保留 AAC 96kbps 音频。

导出检查不再断言固定的 320×366，而是断言实际宽高等于本次边界计算结果，同时继续验证 `qtrle`、15fps、`argb`、AAC 和透明角像素。

## 代码边界

- `server/export-video.js`：负责读取边界、合并边界、计算尺寸和编码。
- `server/index.js`：继续调用同一个导出函数，不新增请求参数。
- `public/index.html` 与 `README.md`：删除固定尺寸表述，说明自动适配。
- 浏览器请求格式、音频上传和下载文件名不变。

不新增 npm 依赖，也不新增 OC 图片上传功能。本次只让已有的两张 OC 素材在导出时自动计算尺寸。

## 测试与验收

- 单元测试覆盖横向、纵向、小尺寸素材的等比例尺寸计算和 8px 边距。
- 编码测试使用张嘴、闭嘴边界不同的透明 PNG，验证使用两者并集且画面不跳动。
- 完全透明或画布尺寸不一致的素材必须明确失败。
- 真实《田林东路.m4a》导出后验证 MOV、`qtrle`、15fps、`argb`、AAC、透明角像素和 282×320 的动态尺寸。
- 浏览器页面显示“自动适应 OC · 剪映透明 MOV”，完整导出后仍出现可点击的 MOV 保存链接。
- 重新生成运行时 ZIP，并从全新解压目录验证构建与启动。

## 非目标

- 不允许用户上传或切换 OC 图片。
- 不提供手动裁切、缩放或输出尺寸控件。
- 不改变嘴型识别、播放预览或剪映导入编码格式。
- 不生成 9:16 成片画布；人物位置和最终大小仍在剪映中调整。

# PAPAlu 低延迟起嘴设计

## 问题与根因

当前 `MouthGate` 对声音上升和下降使用相同的 EMA 平滑。PAPAlu 已经在安静状态时，中等音量讲话需要经过 2–4 个 512 帧缓冲才能越过开启阈值，仅这一段就约为 21–43ms；随后还会叠加音频设备与主线程调度耗时。现有“立即讲话”测试从全新状态直接输入大音量，没有覆盖“先安静、再讲话”的真实链路。

## 修复方案

- 保持当前开启阈值 `0.025`，不靠降低阈值换取响应速度。
- idle 状态使用当前原始 RMS 判断开启；原始 RMS 达到开启阈值时立即进入 talking。
- EMA 继续更新，并继续用于 talking 状态的关闭判断。
- 保持关闭阈值 `0.015` 和 release delay `120ms`，避免字间停顿频繁闭嘴。
- 将 AVAudioEngine tap 缓冲从 512 帧降低到 256 帧；48kHz 输入下单缓冲约从 10.7ms 降至 5.3ms。
- talking 动画 fps、帧序列和角色素材保持不变。

## 测试

- 新增“持续安静后，第一个明显讲话缓冲立即进入 talking”的回归测试。
- 保留安静、release delay 和阈值附近抗抖测试。
- 原生应用编译、原网页 78 项测试和正式素材一致性继续通过。
- 实机播放同一测试声音，确认第一段声音开始时更快切换说话帧，声音停止后仍按约 120ms 闭嘴。

## 不做

- 不降低开启或关闭阈值。
- 不取消 EMA、hysteresis 或 release delay。
- 不增加灵敏度设置界面。
- 不修改动画速度、说话帧或角色图片。
- 不增加音频保存、上传、识别或网络访问。

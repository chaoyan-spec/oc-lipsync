# PAPAlu 实测 RMS 声音门修复设计

## 现场证据

上一轮把闭嘴等待从 120ms 增加到 300ms 后，连续说话仍会进入思考状态。临时诊断模式采集了约 94 秒本机数据，只记录 RMS、缓冲时长和状态，不记录音频。

数据确认：

- AVAudioEngine 实际每次提供约 100ms 音频，而非请求的 256 帧短缓冲。
- 正常讲话中大量 RMS 位于 0.008～0.015。
- 当前 `closeThreshold=0.015` 会把这些真实语音判为安静。
- 现场数据产生约 70 次 talking/idle 切换，最长错误 idle 足以触发思考云。

## 批准的修复

- `openThreshold`: `0.020 → 0.012`
- `closeThreshold`: `0.015 → 0.006`
- `releaseDelay`: `0.30s → 0.60s`
- `smoothingFactor`: 保持 `0.35`

同一现场日志离线回放后，切换次数降到 4 次，talking 覆盖为 97.9%。真正安静后约 0.6～0.8 秒进入 idle，思考云继续在 idle 约 0.5 秒后出现。

## 范围与验证

不增加动态噪声模型、设置页或新动画。使用导致现场误判的真实 RMS 片段作为固定回归序列，同时验证低于 0.012 的背景音不触发、持续静音仍能闭嘴。修复完成后移除临时诊断代码和 `/tmp` 日志。

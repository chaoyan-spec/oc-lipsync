# PAPAlu 可见待机轻摆与快速起嘴设计

## 目标

本轮只修复两个已经通过真人使用发现的问题：

1. 安静时现有 idle 几乎没有可见动作，人物仍像静态贴纸。
2. 开始讲话时，虽然麦克风已经进入 talking，但第一张说话帧嘴型太小，视觉上像晚了一拍。

不增加角色素材、摄像头动作、设置界面或新的动画状态。

## 已确认根因

- 当前呼吸序列使用第 0、7 帧，但两个 PNG 的 SHA-256 完全相同，像素没有变化，因此所谓呼吸不可见。
- talking 状态当前先显示第 1 帧。它只有很小的点状嘴型；明显张嘴的第 2 帧要等下一个 8fps 定时器 tick，最多形成约 125ms 的视觉等待。
- `MouthGate` 已使用原始 RMS 做开启判断，音频 tap 为 256 帧。现有自动测试证明明显声音可在第一个音频缓冲进入 talking，本轮不先降低阈值，以免增加环境噪声误触。

## 方案

### Idle 左右轻摆

保留透明无边框窗口位置不变，只在窗口内部轻微移动和旋转角色视图：

- 水平位移约 `±4pt`。
- 旋转约 `±1°`。
- 一次完整左右往返约 `2.2s`。
- 每次往返后加入短暂停留，并对方向、时长和停留做小范围随机变化，避免固定摆钟感。
- 继续保留现有随机眨眼；轻摆和眨眼可以同时存在。
- 不再把第 0、7 帧切换称作呼吸，因为两帧完全相同。

角色视图保留少量内部边距，避免旋转或位移时裁掉头发和身体边缘。窗口本身不移动，所以不会改变用户拖好的屏幕位置。

### Talking 快速起嘴

- 从 idle 进入 talking 时，立即取消 idle 的移动、旋转和待机定时器。
- 角色视图立即恢复中心位置和正常角度。
- talking 的首帧改为明显张嘴的第 2 帧，而不是点状嘴的第 1 帧。
- 后续继续使用现有 talking 帧和约 8fps 节奏，不修改麦克风阈值、EMA、hysteresis 或 release delay。

这样处理的是“视觉起嘴延迟”，不牺牲噪声稳定性。

## 状态关系

优先级保持不变：

1. `teaching` 临时动作
2. `talking`
3. `idle`

具体行为：

- idle 开始讲话：立即停止轻摆，归中并显示明显张嘴帧。
- talking 停止：保留现有短暂收口序列，随后进入轻摆 idle。
- idle 或 talking 检测到 wave：立即停止当前动画并显示 teaching。
- teaching 结束：根据结束时的实时麦克风状态进入 talking 或 idle。
- 缩放或拖动不改变角色视图内部轻摆逻辑。

## 代码边界

预计只调整：

- `IdleAnimationPlan.swift`：把不可见的伪呼吸计划改为可测试的轻摆节奏参数。
- `PAPAluWindow.swift`：执行角色视图位移/旋转、归中和快速起嘴。
- `IdleAnimationPlanTests.swift`：验证轻摆幅度、节奏和随机范围。
- 必要时调整 app 壳层编译测试和 README。

`MicrophoneMonitor`、`MouthGate`、`WaveDetector` 和角色 PNG 不做行为修改。

## 测试与验收

自动测试至少覆盖：

- idle 轻摆使用非零位移和旋转。
- 轻摆幅度保持克制且不会机械固定。
- talking 的第一帧是明显张嘴帧 2。
- talking、teaching 会取消 idle 并恢复角色归中。
- 现有 MouthGate、wave、状态协调和离线网页测试继续通过。

真人验收重点：

- 安静观察 10 秒，左右轻摆肉眼可见但不抢教程内容。
- 开口时第一下立即出现明显嘴型。
- 环境安静时不会自行进入 talking。
- QuickTime 录屏中人物窗口位置不漂移，边缘不被裁切。

## 明确不做

- 不新增或修改 PAPAlu 图片。
- 不移动整个悬浮窗口。
- 不降低声音阈值。
- 不新增摄像头动作、设置 UI、骨骼、图层拆分或连续动捕。
- 不继续扩展 idle 动作种类。
